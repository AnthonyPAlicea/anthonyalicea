How does code run, and how should you prompt for it?

How does code run?

Code that's running spends most of its time waiting. When something happens, it works through three parts in order. Then it goes back to waiting.

Imagine a recipe app. You can mark any recipe as a favorite.

Lemon Garlic Pasta

25 min

Favorites: 3

Click the heart and watch the three parts below.

  1. EventSomething the program was waiting for happens, like a click or a keystroke.
  2. LogicCode you can't see runs. It checks things and makes decisions.
  3. ResponseSomething on the screen changes.

Waiting for the next event

Interaction design has always worked like this: when the user does something, the system does something back. Code splits that into three parts, and your prompts should too.

Your turn! Fix a vague prompt

When you ask an AI for an interaction, it has to write code for all three parts. Any part your prompt leaves out, the AI guesses.

Someone gave an AI this prompt for the recipe app:

Prompt

Add search to the recipe list.

That one sentence is vague, so the output will be full of AI guesses and assumptions. On the next step you'll fix this prompt one part at a time: event, logic, and response.
